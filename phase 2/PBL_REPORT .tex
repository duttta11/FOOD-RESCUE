% PROJECT ABSTRACT
\sectiontitle{Project Abstract }

\vspace{0.05cm}


\vspace{0.12cm}

\answerbox{4.25cm}{FoodRescue is a smart food rescue and redistribution system designed to connect sources of surplus food, such as restaurants, hostels, households, and events, with NGOs and people in need. It addresses the problem of edible food being wasted while people and support organisations may face shortages. The system records donors food donations, NGOs requirements volunteers and deliveries. It aims to prioritize donations using expiry urgency quantity requirements and distance. A priority queue can order urgent donations hash tables support quick record lookup and a graph with Dijkstra's algorithm helps find suitable delivery routes. The planned solution uses C++ with object-oriented programming and data structures alongside a web interface using HTML CSS and JavaScript. Records are planned to be stored in CSV or text files.}

\vspace{0.90cm}

% UPDATED PROJECT APPROACH
\sectiontitle{Updated Project Approach and Architecture }

\vspace{0.05cm}

\vspace{0.25cm}

\answerbox{7.25cm}{The system is organized into four modules implemented in C++ using OOP and DSA.\\[2pt]
\textbf{Member 1 --- Donor \& Food Donation Module:} \texttt{Donor} and \texttt{FoodDonation} classes; add update and delete donations; food expiry and availability handling; hashing for donor/donation lookup.\\[2pt]
\textbf{Member 2 --- NGO \& Requirement Module:} \texttt{NGO} and \texttt{Requirement} classes; NGO registration/login; management of food requirements; a queue for pending food requests; matching available donations with requirements.\\[2pt]
\textbf{Member 3 --- Volunteer \& Delivery Module:} \texttt{Volunteer} and \texttt{Delivery} classes; volunteer assignment; delivery status tracking; queue/priority queue for deliveries; delivery history.\\[2pt]
\textbf{Member 4 --- Core DSA Integration \& UI:} priority queue for urgent/expiring food; searching and sorting algorithms; overall system integration; menu-driven interface; testing and final documentation.\\[2pt]
The planned architecture also uses a graph and Dijkstra's algorithm for route planning with CSV/text files for storage. HTML CSS and JavaScript are planned for the web interface. The reference proposal does not specify a communication protocol or database server.}

% CHALLENGES
\sectiontitle{Challenges/Roadblocks }

\vspace{0.05cm}


\vspace{0.18cm}

\answerbox{4.45cm}{A key challenge is matching food donations with NGO requirements while considering expiry time quantity and distance together. This will be addressed by maintaining accurate donation and requirement records and using a priority score or priority queue to process urgent donations first. Another challenge is validating expiry and availability so that expired or unavailable food is not offered for redistribution. Route planning depends on representing locations and roads correctly so a predefined graph will be used for the initial version and Dijkstra's algorithm will calculate routes. The team must also coordinate modules without duplicating or losing records. Clear class responsibilities module-level tests and end-to-end tests using sample records will help address these issues. Real-time GPS live maps and food-safety certification are outside the initial scope stated in the proposal.}
